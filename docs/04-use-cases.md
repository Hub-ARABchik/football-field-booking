# Сценарии использования системы (Use Case)

## 1. Общая информация

Use Case описывает взаимодействие пользователей с системой Football Field Booking System (FFBS). Документ определяет основные действия пользователей и последовательность выполнения операций.

## 2. Акторы системы

В системе предусмотрены следующие основные акторы:

| Актор | Описание |
|---|---|
| Гость | Пользователь, который просматривает доступные площадки |
| Клиент | Зарегистрированный пользователь, который ищет и бронирует площадки |
| Владелец площадки | Пользователь, который добавляет площадки и управляет их расписанием |

## 3. Основные сценарии использования

### 3.1. Регистрация пользователя

1. Пользователь открывает страницу регистрации.
2. Вводит имя, фамилию, номер телефона, электронную почту и пароль.
3. Выбирает тип учетной записи.
4. Система проверяет введённые данные.
5. При успешной проверке создаётся учетная запись.

### 3.2. Авторизация пользователя

1. Пользователь открывает страницу входа.
2. Вводит электронную почту и пароль.
3. Система проверяет учетные данные.
4. При успешной проверке пользователь получает доступ к своей учетной записи.

### 3.3. Просмотр футбольных площадок

1. Пользователь открывает каталог площадок.
2. Система получает список доступных площадок.
3. Пользователь просматривает информацию о выбранной площадке.

### 3.4. Добавление футбольной площадки

1. Владелец авторизуется в системе.
2. Открывает раздел управления площадками.
3. Заполняет информацию о новой площадке.
4. Отправляет данные на сервер.
5. Система проверяет и сохраняет информацию в базе данных.

### 3.5. Поиск футбольной площадки

1. Клиент открывает каталог.
2. Вводит параметры поиска.
3. Система обрабатывает запрос.
4. Отображаются площадки, соответствующие заданным параметрам.

### 3.6. Бронирование площадки

1. Клиент выбирает футбольную площадку.
2. Просматривает доступное расписание.
3. Выбирает дату и свободный временной интервал.
4. Отправляет запрос на бронирование.
5. Система проверяет доступность выбранного времени.
6. При успешной проверке создаётся бронирование.

### 3.7. Управление расписанием

1. Владелец авторизуется в системе.
2. Открывает раздел управления расписанием.
3. Выбирает площадку.
4. Добавляет или изменяет доступные временные интервалы.
5. Система сохраняет изменения.

## 4. Альтернативные сценарии

- Если пользователь вводит некорректные данные, система отображает сообщение об ошибке.
- Если электронная почта уже зарегистрирована, система сообщает о необходимости использовать другой адрес.
- Если выбранное время уже занято, система предлагает выбрать другой интервал.
- Если пользователь не авторизован, система предлагает выполнить вход.

## 5. Результат

Use Case определяет основные варианты взаимодействия пользователей с FFBS и служит основой для проектирования интерфейса, серверной логики и базы данных.
